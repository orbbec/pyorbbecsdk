5.19. 结构化数据读写

本节接口在 Python Wrapper 2.1.4 中可用。可访问的属性仍取决于设备和固件支持情况。

5.19.1. 选择最简单的接口

日常设备操作应优先使用已有的强类型 API。它直接接收或返回 Python 配置对象，因此不需要属性 ID、bytes、to_bytes() 或 from_bytes()。

任务

推荐读取 API

推荐写入 API

device.get_temperature()

只读

device.get_baseline()

只读

HDR

device.get_hdr_config()

device.set_hdr_config(config)

多设备同步

device.get_multi_device_sync_config()

device.set_multi_device_sync_config(config)

深度工作模式

device.get_depth_work_mode()；支持模式：device.get_depth_work_mode_list()

只读

IP 信息方法不返回完整配置标志或静态 IP 记录。如需这些字段，请参见下方 IP 特殊情况。签名和成员参见核心接口、数据结构和流配置。

5.19.2. 接口速览

当结构化属性没有合适的强类型封装（如彩色 AE ROI），或应用需要按属性 ID 统一访问时，使用通用接口。Device.get_structured_data(property_id) 返回独立持有的 Python bytes；Device.set_structured_data(property_id, data) 写入字节。使用 Config.from_bytes(data)bytes(data) 和 config.to_bytes() 显式转换。属性 ID 决定操作，字节本身不携带 Python 类型。以下示例说明此通用流程。

5.19.3. 基本用法

示例中，device 是已打开的 pyorbbecsdk.Device。例如：

import pyorbbecsdk as ob

context = ob.Context()
devices = context.query_devices()
if devices.get_count() == 0:
    raise RuntimeError("No device connected")
device = devices.get_device_by_index(0)

彩色 AE ROI 是通过通用接口访问的属性示例。读取后，使用匹配的结构体解码坐标：

prop = ob.OBPropertyID.OB_STRUCT_COLOR_AE_ROI
if not device.is_property_supported(prop, ob.OBPermissionType.PERMISSION_READ):
    raise RuntimeError("Color AE ROI is not readable")
roi = ob.OBRegionOfInterest.from_bytes(device.get_structured_data(prop))
print(roi.x0_left, roi.y0_top, roi.x1_right, roi.y1_bottom)

写入 AE ROI 前，请启动对应数据流，并在收到首帧后刷新 ROI，详见下文。

5.19.4. 载荷规则

  • 二进制输入必须为 bytes。先用 bytes(buffer) 转换 bytearray 或 memoryview。内嵌零字节会保留。

  • set_structured_data() 拒绝空数据和长度超过 uint32_t 的数据。

  • from_bytes() 要求长度与结构体精确匹配。to_bytes() 返回独立副本。使用 len(config.to_bytes())，不要使用 sys.getsizeof(config)。

  • 载荷使用当前 SDK 的原生字节序和紧凑结构体布局，不是用于文件存储或跨平台交换的可移植序列化格式。

  • 仅提供结构体载荷：不要包含 I2C 头、操作码、请求 ID、命令版本或响应错误码。完整协议数据包请使用设备二进制数据接口。

  • 对于普通属性，设置接口直接转发字节，不验证属性与类型是否匹配，也不强制表中的长度。调用者必须匹配属性和布局。长度相同不代表两种类型可以互换。

5.19.5. 检查支持情况与权限

prop = ob.OBPropertyID.OB_STRUCT_COLOR_AE_ROI
readable = device.is_property_supported(prop, ob.OBPermissionType.PERMISSION_READ)
writable = device.is_property_supported(prop, ob.OBPermissionType.PERMISSION_WRITE)
print("readable:", readable, "writable:", writable)

枚举成员、Python 结构体、字节转换支持和设备支持是不同条件。权限检查成功，不排除后续因设备状态、参数限制或固件行为导致 SDK 错误。

无效二进制输入引发 TypeError；无效长度、未知读取布局和绑定层限制引发 ValueError。设备访问失败通过 OBError 报告。

5.19.6. 只读数据

对于温度，强类型 API 已直接返回结构体：

temperature = device.get_temperature()
print(temperature.cpu_temperature, temperature.ir_left_temperature)

温度可能在两次读取间变化或包含 NaN。请按属性比较有意义的字段，不要要求原始字节完全一致。存在通用读取接口并不意味着该值可写。

5.19.7. 读取、修改、验证与恢复

AE ROI 使用 OBRegionOfInterest，字段为边界坐标 (x0_left, y0_top, x1_right, y1_bottom)。RGB 裁剪使用 OBRect (x, y, width, height)，两种布局不能互换。

某些设备和固件要求在推流状态下配置 AE ROI。启动对应数据流，等待首帧，然后读取 ROI 作为原始配置。坐标必须在该帧尺寸范围内，改变分辨率后应刷新 ROI。必须启用自动曝光，ROI 才会影响曝光调节。

运行此示例前，请按阻塞轮询模式流程启动彩色流。在此使用同一 pipeline 及其 device = pipeline.get_device()，并沿用基本用法中的 import pyorbbecsdk as ob 别名。保持 Pipeline 运行直至恢复完成，之后在不再需要时停止。

prop = ob.OBPropertyID.OB_STRUCT_COLOR_AE_ROI
if not device.is_property_supported(prop, ob.OBPermissionType.PERMISSION_READ_WRITE):
    raise RuntimeError("Color AE ROI is not readable/writable")

for _ in range(5):
    frames = pipeline.wait_for_frames(1000)
    color = frames.get_color_frame() if frames is not None else None
    if color is not None:
        break
else:
    raise RuntimeError("No color frame received")

original = device.get_structured_data(prop)  # Read after the first color frame.
config = ob.OBRegionOfInterest.from_bytes(original)
if config.x1_right - config.x0_left <= 16 or config.y1_bottom - config.y0_top <= 16:
    raise RuntimeError("ROI is too small for this example")
config.x0_left += 8
config.y0_top += 8
config.x1_right -= 8
config.y1_bottom -= 8
if not (0 <= config.x0_left < config.x1_right < color.get_width()
        and 0 <= config.y0_top < config.y1_bottom < color.get_height()):
    raise RuntimeError("Target ROI is outside the active color frame")

try:
    device.set_structured_data(prop, config.to_bytes())
    actual = ob.OBRegionOfInterest.from_bytes(device.get_structured_data(prop))
    fields = ("x0_left", "y0_top", "x1_right", "y1_bottom")
    expected = tuple(getattr(config, field) for field in fields)
    observed = tuple(getattr(actual, field) for field in fields)
    if observed != expected:
        raise RuntimeError("ROI readback differs; check firmware limits/update timing")
finally:
    device.set_structured_data(prop, original)
    if device.get_structured_data(prop) != original:
        raise RuntimeError("Failed to restore original ROI")

对于深度 AE ROI，使用 OB_STRUCT_DEPTH_AE_ROI，通过 frames.get_depth_frame() 等待深度帧，并使用深度帧尺寸。

某些属性异步生效或会量化数值。请根据设备调整等待时间和比较方式，并将恢复失败视为失败。回读仅验证配置读写流程，不验证图像效果。IP 配置可能导致设备断连，不要套用此自动恢复模式。

5.19.9. 已有 API 与特殊情况

请使用以下封装接口完成对应任务。本节列出推荐方法和剩余约束；正常使用这些方法时无需手动序列化属性。

5.19.9.1. 多设备同步

使用 device.get_multi_device_sync_config() 获取 OBMultiDeviceSyncConfig，修改所需字段，再将对象传入 device.set_multi_device_sync_config(config)。SDK 负责协议选择。硬件连接与配置流程请参见多相机同步。

如应用需要通用访问，对应属性使用公开的 25 字节 OBMultiDeviceSyncConfig 布局。旧版 OBDeviceSyncConfig 和固件协议包属于不同表示形式。序列化的 trigger_out_enable 字节必须为 0 或 1。

5.19.9.2. 深度工作模式

使用 device.get_depth_work_mode() 读取当前模式，使用 device.get_depth_work_mode_list() 获取有效模式。切换前停止所有流，选择列表中的完整项并传给 device.set_depth_work_mode(mode)。将返回状态与 ob.OBStatus.STATUS_OK 比较。完整示例参见深度工作模式。

对于未填充 get_depth_work_mode().tag 的 SDK 版本，请从支持模式列表的对应项获取 tag。需处理专用 API 的 SDK 错误；仅有原始属性权限不能证明该流程受支持。

公开的 OBDepthWorkMode 包含 tag；内部的 OBDepthWorkModeInternal 包含 option_code。两者都是 52 字节，但含义不同。切换模式时应保留设备提供的列表项，不要自行构造内部载荷。

5.19.9.3. 设备错误状态

使用 device.get_device_state() 直接获取整数状态掩码，再用 OBDeviceErrorCode 解释各位，无需字节转换。此状态只读，没有设置接口，SDK 可能返回缓存信息。

需要结构化属性接口时，OB_STRUCT_DEVICE_ERROR_STATE 通过专用 SDK 状态 API 返回 OBDeviceErrorState.error_code，写入会被拒绝。低 32 位为错误位，高 32 位为警告位。SDK 将第 63 位 DEVICE_WARNING_LOG_OVERFLOW 描述为状态信息缓存标志。完整枚举表请参见数据结构。

5.19.9.4. 可变及不可用布局

通用读取接口不支持 OB_STRUCT_DEPTH_PRECISION_SUPPORT_LIST（可变长度）或 OB_STRUCT_COLOR_SYNCED_EXPOSURE_PARAM（布局尚未适配）。此版本也未提供读取这两种载荷的专用封装。设备支持检查不能补足缺失布局或安全的长度查询 API。

发现 IMU 能力时，使用 device.get_sensor_list() 选择加速度计或陀螺仪传感器，再调用 sensor.get_stream_profile_list()。此公开接口避免依赖内部预设列表权限。它仅发现 IMU 流配置，不能替代上述不支持的载荷。OBImuPresetList 自身为固定 68 字节布局，最多含 16 项；count 只读，values 暴露有效条目。

5.19.9.5. IP 配置与其他字段约定

使用 device.set_ip_config(config) 直接写入 OBNetIpConfigV2 或 OBDeviceIpAddrConfig 对象。传入 V2 对象时，Wrapper 会检查 V2 读写支持；若不支持，则转换为 V1 配置并回退。V1 对象直接写入 V1。操作流程请参见 IP 配置。

查看当前地址时，先获取 info = device.get_device_info()，再使用 info.get_device_ip_address()、info.get_device_subnet_mask() 和 info.get_device_gateway()。这些方法报告地址信息；读取完整 V1/V2 配置字段或静态 IP 记录，仍需在支持时使用对应结构化属性。

这些高级读取中，V1 使用 dhcp；V2 使用 flags（DHCP 掩码 0x01、持久 IP 掩码 0x02）；IP 地址字段为点分字符串。OB_STRUCT_DEVICE_STATIC_IP_CONFIG_RECORD 使用 OBDeviceIpAddrConfig，且只读。通用 IP 写入仅针对指定属性，不执行强类型设置接口的 V2 到 V1 回退。IP 修改可能中断连接，因此不要套用 ROI 示例的自动恢复模式。

其他结构体应保留 reserved 字段。HDR 在紧凑布局中占 18 字节，已有 get_hdr_config() / set_hdr_config(config)。AWB 增益顺序为 r_gain、b_gain、g_gain；写入前请按设备要求处理自动白平衡。OBDeviceTime 包含 time 和 rtt；较旧的时钟单位可能取决于设备频率。

5.19.10. 类型别名

类型别名为 OBSerialNumber = OBDeviceSerialNumber、OBNetIpConfig = OBDeviceIpAddrConfig，以及 OBDepthWorkMode_Internal = OBDepthWorkModeInternal。

5.19.11. 限制

仅扁平、固定布局结构体支持字节转换。这不是 SDK 对象、指针或可变数组的通用序列化。通用设置接口接收 bytes，不意味着读取接口知道该属性布局，也不意味着设备允许写入。

SDK 的普通结构化读取先复制数据，再报告返回长度，不强制传入容量。因此读取依赖设备和 SDK 遵守已登记布局。调用后的长度检查可发现 ABI 不匹配，却无法防止 SDK 缓冲区越界。不要使用空缓冲区或反复扩大缓冲区探测未知长度。安全支持任意载荷需要具有容量感知能力的 SDK API。
