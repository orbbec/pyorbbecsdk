7.2. 安装问题

7.2.1. Linux 上找不到设备

问题：运行示例时提示“No device found”，或无法检测到相机。

解决方法：

这通常是 USB 权限问题：当前用户没有访问 USB 设备的权限。

快速修复——运行环境配置脚本：

# Option 1: From repository
python scripts/env_setup/setup_env.py

# Option 2: From installed package (v2.1.0+)
# 1. Get pyorbbecsdk installation path
python -c "import pyorbbecsdk, os; print(os.path.dirname(pyorbbecsdk.__file__))"
# Example output: /path/to/site-packages/pyorbbecsdk
# 2. Run setup.py(replace with the path from step 1)
python /path/to/site-packages/pyorbbecsdk/shared/setup_env.py

手动修复——安装 udev 规则：

  1. 检查设备 PID：

    lsusb | grep 2bc5

  2. 编辑 udev 规则文件：

    sudo nano /etc/udev/rules.d/99-obsensor-libusb.rules

  3. 添加以下内容（将 your_pid_here 替换为实际 PID）：

    SUBSYSTEM=="usb", ATTR{idProduct}=="your_pid_here", ATTR{idVendor}=="2bc5", MODE:="0666", OWNER:="root", GROUP:="video"

  4. 重新加载 udev 规则：

    sudo udevadm control --reload-rules && sudo service udev restart && sudo udevadm trigger

注意：如果不安装 udev 规则，每次运行 SDK 脚本都需要 sudo。

7.2.2. macOS 上权限不足

问题：在 macOS 上运行时出现 Permission denied 或 Library not loaded 错误。

解决方法：

使用 sudo -E 保留环境变量（使用虚拟环境时尤其重要）：

sudo -E python examples/beginner/02_depth_visualization.py

-E 选项保留 Python 环境变量，确保能访问虚拟环境中的软件包。

7.2.3. Windows 上的 ImportError

问题：Windows 上出现 ImportError: DLL load failed 或类似错误。

解决方法：

  1. 确保使用 64 位 Python（必需）：

    python -c "import struct; print(struct.calcsize('P') * 8)"
# Should output: 64

  2. 安装 Visual C++ Redistributable（通常已预装，但可能需要重新安装）

  3. 确认 Python 版本与 wheel 匹配（例如 cp311 对应 Python 3.11）：

    python --version

7.2.4. Python 版本不匹配

问题：安装时出现 No matching distribution found 错误。

解决方法：

检查 Python 版本是否在支持范围内（3.8–3.14）：

python3 --version

如果使用版本管理工具（pyenv、conda），请确认使用了正确的 Python：

which python3

支持的 Python 版本：3.8、3.9、3.10、3.11、3.12、3.13、3.14

7.2.5. 离线安装失败

问题：安装 wheel 时出现平台标签错误。

解决方法：

确保下载的 wheel 与以下条件匹配：

  • 操作系统（Linux/macOS/Windows）

  • 架构（x86_64/ARM64）

  • Python 版本（cp38、cp39、cp310、cp311、cp312、cp313、cp314）

检查平台标签：

# For Linux/macOS
python3 -c "import platform; print(platform.machine()); print(platform.system())"
# For Windows
python -c "import platform; print(platform.machine()); print(platform.system())"

wheel 命名规则：

  • Linux x86_64: pyorbbecsdk2-*-cp3X-cp3X-linux_x86_64.whl

  • Linux ARM64: pyorbbecsdk2-*-cp3X-cp3X-linux_aarch64.whl

  • macOS ARM64: pyorbbecsdk2-*-cp3X-cp3X-macosx_11_0_arm64.whl

  • Windows x64: pyorbbecsdk2-*-cp3X-cp3X-win_amd64.whl

7.2.6. 包名混淆

问题：应该安装 pyorbbecsdk 还是 pyorbbecsdk2？导入名与包名不同。

解决方法：

从 2.0.18 版本开始，在线（PyPI）和离线软件包均使用 pyorbbecsdk2 这一名称：

# Install from PyPI
pip install --upgrade pyorbbecsdk2

# Install offline wheel
pip install pyorbbecsdk2-2.x.x-xxx.whl

代码中导入：import pyorbbecsdk（模块名保持不变）

验证安装：

pip show pyorbbecsdk2 | grep Version

7.2.7. Open3D 与 NumPy 版本兼容性

问题：为什么 Open3D 和 NumPy 有版本限制？同时使用时出现兼容性错误。

解决方法：

由于 ABI（应用程序二进制接口）兼容性要求，Open3D 对 NumPy 版本有特定限制。使用不兼容版本可能导致运行时错误或崩溃。

要点：

  • Open3D 的 NumPy 依赖：Open3D 针对特定 NumPy 版本编译。使用与构建时不同的 NumPy 版本可能导致：

    • 调用 Open3D 函数时出现 RuntimeError

    • 段错误

    • 计算结果不正确

  • 推荐兼容版本：

Open3D 版本

兼容的 NumPy 版本

0.16.x

1.21 - 1.23

0.17.x

1.21 - 1.24

0.18.x

1.22 - 1.26

  • 最佳实践：请始终查看 Open3D 官方入门指南，了解最新兼容性信息：Open3D 入门指南

  • 如果遇到问题：

    # Check your current versions
python -c "import numpy; print(f'NumPy: {numpy.__version__}')"
python -c "import open3d; print(f'Open3D: {open3d.__version__}')"

# Install compatible versions
pip install numpy==1.23.5 open3d==0.17.0

7.3. 构建问题

7.3.1. 找不到 uv 命令

问题：运行构建脚本时出现“uv: command not found”。

解决方法：

确保 uv 已安装并位于 PATH 中：

# Install uv (if not already installed)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Add to ~/.bashrc or ~/.zshrc
export PATH="$HOME/.local/bin:$PATH"

7.3.2. CMake 配置失败

问题：构建失败，出现“CMake configuration failed”错误。

解决方法：

检查 CMake 版本和 Python 开发头文件：

# Check CMake version (requires 3.15.0+)
cmake --version

# Install Python development headers (Linux)
# Ubuntu/Debian:
sudo apt-get install python3-dev build-essential

# CentOS/RHEL/Fedora:
sudo yum install python3-devel gcc-c++

7.3.3. 离线模式下找不到 pybind11

问题：离线构建失败，出现“pybind11 not found”错误。

解决方法：

默认构建脚本会重建各版本环境，仅复制 venv* 不能为此流程保留 pybind11。请在匹配的联网机器上准备实际构建所需的 uv 缓存和 Python 解释器，再随项目传输，并提供原生构建工具链。

完整缓存准备及平台命令参见离线构建。如需复用有效的本地环境，请先激活，再使用 --offline --no-sync（PowerShell：-Offline -NoSync）；隔离 wheel 构建仍需要缓存的构建依赖。不要使用 uv pip install -e . 准备干净仓库：CMake 必须先生成 install/lib。

7.3.4. Windows 构建失败，找不到 Visual Studio

  • C++ 构建工具

  • Windows SDK

7.4. 运行时问题

    frames = pipeline.wait_for_frames(5000)  # Wait up to 5 seconds

  2. 确认数据流可用：运行相机入门示例，检查支持的数据流：

  3. 处理前确保帧有效：

    if frames is None:
    continue
color_frame = frames.get_color_frame()
if color_frame is None:
    continue

  4. 尝试快速入门：零配置方式会自动处理默认设置：

    python examples/quick_start.py

    if color_frame is not None:
    color_image = frame_to_bgr_image(color_frame)

7.5.3. macOS 相机与终端授权

问题：在 macOS 上首次运行访问相机的示例时，出现权限错误或相机无法工作。终端似乎没有相机访问权限。

解决方法：

macOS 要求应用访问相机等硬件资源前获得明确授权。首次在终端运行访问相机的 Python 脚本时，macOS 会提示授权。

授予终端相机访问权限的步骤：

  1. 首次运行：第一次运行相机示例时，macOS 会显示系统对话框：

    “Terminal”希望访问相机。

    点击“Allow”（允许）或“OK”（好）。

  2. 如果曾误拒绝权限：

    • 打开系统设置（旧版 macOS 为系统偏好设置）

    • 进入隐私与安全性 → 输入监控

    • 在列表中找到 Terminal（如使用 iTerm2，则找到 iTerm2）

    • 打开开关

  3. 验证权限已授予：

    # Run any camera example
python examples/beginner/01_hello_camera.py

    如果相机正常工作且不再提示权限，说明授权完成。

注意：每个终端应用仅需授权一次。授权后，从该终端执行后续相机操作无需再次提示。

7.6. 相机与数据流

7.6.1. 帧同步失败

问题：彩色和深度帧不同步，或时间戳不匹配。

解决方法：

  1. 使用 wait_for_frames() 获取同步帧：

    frames = pipeline.wait_for_frames(1000)  # Returns synchronized FrameSet

depth = frames.get_depth_frame()

  2. Windows 上请确保已完成元数据注册（参见 Windows 上的元数据问题）

  3. 检查时间戳元数据：

    color_timestamp = color_frame.get_timestamp()
depth_timestamp = depth_frame.get_timestamp()
diff = abs(color_timestamp - depth_timestamp)

7.6.2. 分辨率或帧率配置问题

问题：无法设置特定分辨率或帧率，或配置失败。

解决方法：

先检查可用的流配置：

from pyorbbecsdk import Config, OBSensorType, OBFormat

config = Config()
profiles = pipeline.get_stream_profile_list(OBSensorType.COLOR_SENSOR)

# List all available profiles
for i in range(profiles.get_count()):
    profile = profiles.get_stream_profile_by_index(i).as_video_stream_profile()
    print(f"{profile.get_width()}x{profile.get_height()} @ {profile.get_fps()}fps")

# Try specific profile with fallback
try:
    color_profile = profiles.get_video_stream_profile(1280, 720, OBFormat.RGB, 30)
except:
    color_profile = profiles.get_default_video_stream_profile()

config.enable_stream(color_profile)
pipeline.start(config)

7.7. 配置

7.7.1. 如何配置或禁用 SDK 日志

问题：如何修改日志级别或禁用 SDK 日志？

解决方法：

编辑 OrbbecSDKConfig.xml 配置文件以修改日志级别。

步骤：

  1. 找到配置文件

    包内 XML 位于 <Location>/pyorbbecsdk/OrbbecSDKConfig.xml，其中 <Location> 是发行包的安装目录。请使用当前 Python 定位文件，不必依赖 pip：

    python -c "from pathlib import Path; import pyorbbecsdk; print(Path(pyorbbecsdk.__file__).resolve().parent / 'OrbbecSDKConfig.xml')"

    仅编辑安装目录中的文件，不能保证默认 Context() 会加载它。编辑后，请在创建设备或管线之前，将输出的配置路径显式传入上下文构造函数：

    from pathlib import Path
import pyorbbecsdk
from pyorbbecsdk import Context, Pipeline

config_path = Path(pyorbbecsdk.__file__).resolve().parent / "OrbbecSDKConfig.xml"
context = Context(str(config_path))
devices = context.query_devices()
if len(devices) == 0:
    raise RuntimeError("No device found")
pipeline = Pipeline(devices[0])

  2. 修改日志级别

    打开 XML 文件，找到 <Log> 节点：

    <Log>
    <FileLogLevel>1</FileLogLevel>          <!-- Change this from 1 to 5 -->
    <ConsoleLogLevel>3</ConsoleLogLevel>
</Log>

    将 FileLogLevel 改为 5：

    <Log>
    <FileLogLevel>5</FileLogLevel>          <!-- 5 = NONE, disables logging -->
    <ConsoleLogLevel>3</ConsoleLogLevel>
</Log>

日志级别取值：

值

级别

说明

0

DEBUG

调试信息

1

INFO

常规信息（默认）

2

WARN

警告消息

3

ERROR

错误消息

4

FATAL

致命错误

5

NONE

禁用日志

7.8.2. 如何更新固件

解决方法：

python examples/beginner/09_device_firmware_update.py
